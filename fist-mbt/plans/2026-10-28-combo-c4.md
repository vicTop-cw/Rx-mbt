## 流程与判据

1. **寻虫**：各 lane 只读扫描，产出 `fist-mbt/reports/2026-10-28-c4-bugfind-<lane>.md`（每条：位置/证据/复现/建议/裁决建议）。
2. **修复**：Lead triage 后各 lane 修 P0/P1/P2（不改公开 API 签名、不新增功能），补回归 → `c4-fix-<lane>.md`。
3. **打磨**：弱断言/重复代码/文档数字/注释 → `c4-polish.md`（Lead 汇总 + 各 lane 变更）。
4. **验证**：qa-platform 串行三入口四步 gate + `verify_interop --strict --require-negative` + `moonfmt` 幂等 +
   契约计数复算 → `c4-verify.md`；Lead 独立复跑。
5. **清整**：生成物 untrack/ignore、临时目录、报告数字、工作树干净 → `c4-tidy.md` + commit。

**单轮判绿硬门**：`moon check` 三目标 0 error；Windows(bash/ps1) + WSL 四步 `RESULT: PASS`（612/825/612 或更新数）；
互操作 `--strict --require-negative` 全 PASS；fmt 幂等 0；`git status` 干净（生成物不再弄脏工作树）。
