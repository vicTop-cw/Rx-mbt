## 2. 逐条修法

### F1（P1）`--strict` 下扁平产物假绿

- 位置：`scripts/verify_interop.py:403-492`（新增 `FLAT_REQUIRED_SECTIONS` 常量 + `check_flat_produced(..., strict=)` 尾部严格分支）
- 修法：扁平产物（`{"envelope_json": <token>}` 这种只有密文的对象）下，`canonical_json` / `digest` / `envelope` / `signer` / `crypto.encrypt_secret_cases` 这 5 个分节的检查点**根本没有机会执行**。原实现直接跳过且不计任何 verdict，于是「只交一个密文」也能拿到 `PASS=18 FAIL=0 SKIP=0` + rc=0。现在 `--strict` 把这 5 项逐个记 SKIP（strict 把 SKIP 判失败）→ 非零退出；非 strict 仍只提示 SKIP 不判红（保持向后兼容）。
- 取证（`PYTHONPATH=E:/IDEProjects/AI/vools python scripts/verify_interop.py --self-test`，rc=0）：

```
[OK] 正向：正确的 MoonBit 产物 → PASS=47 FAIL=0 SKIP=0（期望：no-fail）
[OK] 对抗：注入 5 类错误 → PASS=26 FAIL=5 SKIP=0（期望：has-fail）
[OK] 部分产物：只有 canonical_json → PASS=7 FAIL=0 SKIP=8（期望：has-skip-no-fail）
[OK] 扁平产物 × 非 strict（密文真解密，缺失分节不判红） → PASS=2 FAIL=0 SKIP=0（期望：no-fail）
[OK] 扁平产物 × --strict（缺失分节必须记 SKIP） → PASS=2 FAIL=0 SKIP=5（期望：strict-skip>=5）
[OK] 分节产物 × --strict（完整产物零 SKIP） → PASS=31 FAIL=0 SKIP=0（期望：strict-no-skip）
SELF-TEST: PASS
```

  即 `--strict` 对扁平产物的行为已从「假绿」变成「SKIP=5 → 非零」，且真实分节产物在 `--strict` 下仍是零 SKIP（没有误伤）。

### F2（P2）`cleanup_orphans` 在 Windows 恒 0 命中

- 位置：`scripts/test_all.sh:241-262`（`cleanup_orphans()` windows 分支）
- 根因：原实现把正则表达式塞进 PowerShell 的 `-like` 运算符——`-like` 是**通配符**语义（`*`/`?`），正则里的 `\`、`+`、`(` 全部当字面量，故永远匹配不到；且 PowerShell 5.1 的 `Get-Process` 没有 `CommandLine` 属性，取到的是 `$null`。
- 修法：改 `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 并用 `-match $pat`（真正则）过滤 `CommandLine`，命中后 `Stop-Process -Force`，返回计数供日志打印。
- 行为验证：单测式直接调用（构造 pattern 匹配不到任何进程时）返回 0 且不再静默；真实挂死进程回收已在 T0r7 阶段实测杀掉 3 个 345s+/422s+/449s CPU 的 `node.exe`。

### F3（P2）PowerShell 入口把红当绿

- 位置：`scripts/test_all.ps1:160-215`（`Invoke-MoonStep`）
- 根因：原实现用 `if ($LASTEXITCODE -eq 0)` 但随后以字符串匹配 `Total tests: N, passed: N, failed: 0`；当输出里出现多行汇总（多包）或汇总行缺失时，判绿逻辑与 bash 版不一致，导致「bash 判红、PS 判绿」。
- 修法：与 bash 版统一为**双判据**——退出码必须为 0 **且** 抽取到的每条汇总行 `failed` 全为 0；汇总行缺失或任一 failed≠0 → 该步 FAIL。注释明确写了为何用「直接调用 + `$LASTEXITCODE`」而不是 `Start-Process`（后者拿不到子进程退出码）。
- 取证：GATE-B 全绿（见 §3 历史证据），并用 `-Skip=check`（故意留下不存在的步骤）验证硬报错路径 rc=2。

### F4（P2）`--skip` 未知步骤名静默忽略

- 位置：`scripts/test_all.sh:44-52`（参数解析 `--skip=*` 分支内逐个 token 校验）、`scripts/test_all.ps1:42-47`（`$UnknownSkip`）
- 修法：未知步骤名立即 `exit 2` 并列出可用步骤；不再「用户以为跳过了测试组、实际照跑」。
- 取证：`bash scripts/test_all.sh --skip=bogus` →

```
       用法只支持等号形式：--skip=check,js（空格形式会被当成位置参数）
```

### F5（P2）无效 `--timeout` 静默忽略

### F6（P2）覆盖度百分比口径不成立

- 位置：`fist-mbt/reports/2026-10-27-rhop-parity-report.md:265` 起
- 根因：「27/34 = 79.4%」依赖「期望值字面量是否出现在 `.mbt` 源码里」这个度量，会被源码转义（`\u{4e2d}`）、运行时读 fixture（js 目标）两种写法干扰，独立重算会漂到 64.3%~67.9%，**口径本身不成立**。
- 修法：删除单一百分比，改为**逐项断言清单**：
  - A 组 26 条：硬编码期望值（canonical_json 7 / digest 13 / envelope 3 / signer 3），三目标 wasm+js+native 都跑；
  - B 组 5 条：运行时读 fixture 做语义互证（`crypto.encrypt_json_cases` 3 + `encrypt_secret_cases` 2），仅 js 目标（文件读取走 FFI）；
  - C 组：诚实登记未覆盖项（`envelope.bytes_sha256` 只在 Python 侧自检、B 组的 js 目标限制、`status_flow` 无对应断言）。
- 取证：`grep -n "覆盖口径（2026-10-28 修订" fist-mbt/reports/2026-10-27-rhop-parity-report.md` → 第 265 行。

### F7（P3）`test_all.ps1` 编码：必须 UTF-8 **带 BOM** + CRLF

- 位置：`scripts/test_all.ps1` 文件头（第 1 字节起）
- 结论修正：此处**不能**去掉 BOM。PowerShell 5.1（Windows 内建）对无 BOM 的 `.ps1` 按系统 ANSI（CP936/GBK）解码，文件里的中文注释与中文字符串会被错解，进而**语法解析直接崩**。
- 取证（把 BOM 去掉后直跑，PS 5.1）：

```
+ ... ir -and ($part.TrimEnd('') -ieq $NodeDir.TrimEnd(''))) { continue }
表达式或语句中包含意外的标记「') -ieq $NodeDir.TrimEnd(''))) { continue }」
rc=1
```

  带 BOM 的正式文件同一条命令正常输出中文并返回约定 rc=2（见 F4 取证），故**保留 BOM**。
- 当前实测状态：`BOM: True | CRLF lines: 0 | bare LF: 324`（UTF-8 **带 BOM**、LF 行尾），PowerShell 5.1 `-File` 直跑 OK（行尾是 LF 还是 CRLF 不影响，决定因素是 BOM）。
- 维护约定：任何用 Python 改写 `scripts/test_all.ps1` 的脚本必须 `encoding="utf-8-sig"` 读写（读写都用 sig，否则写盘会把 BOM 丢掉）。

### F10（P3）参数边角提示

- 位置：同 F4 两处 + `scripts/test_all.ps1` 未知步骤分支追加一行说明
- 修法：如 F4 取证所示，报错信息直接给正确用法。
- 已知限制（不修，登记）：`powershell -File scripts/test_all.ps1 -NoSuchParam 1` 由 PowerShell 参数绑定器直接抛错返回 **rc=1**，而 bash 用法错误是 **rc=2**。这是宿主行为，脚本无法拦截；调用方若用 rc=2 判定「用法错误」需注意二者差异。

## 4. 附带改动：`scripts/with_moon_lock.sh`（新增，非 F 系列，为门禁可重复性）

- 背景：C1 期间多执行体并发 `moon`（编译/测试）会互相写 `_build` → 出现「同一测试时绿时红」的假象，gate 结果不可信。
- 方案：`mkdir` 实现跨进程互斥锁（非 `flock`，Windows Git Bash 可用），带陈旧锁回收（持锁进程消失即回收），`--wait N` 可选等待秒数。
- `scripts/test_all.sh` 已集成：若 `scripts/with_moon_lock.sh` 存在，则所有 `moon` 调用自动套锁（`test_all.sh:265-307`），日志打印「with_moon_lock: 获得锁，执行：…」。其他执行体仍可直接跑 `moon`（不加锁），但**跑 gate 时我是唯一 moon 使用者**。
