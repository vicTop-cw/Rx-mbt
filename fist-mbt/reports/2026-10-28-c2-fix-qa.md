## 2. 逐条修法

### Q1 + Q2（P1）超时清理：pattern 正确化 + 收窄，杜绝误杀

**test_all.sh**（`cleanup_orphans` 前）：

```bash
REPO_TOKEN=$(basename "$PROJECT_DIR")
# pattern 用 `.` 表示「任意单个分隔符」：同时命中 Windows `\` 与 POSIX `/`，
# 免去 `[\\/]` 在 bash/PS/pkill 三层转义下极易写坏的写法（C2 实测：写坏即恒 0 命中）。
CLEAN_PAT_JS="${REPO_TOKEN}._build.(wsl.)?js.debug.test"
CLEAN_PAT_NATIVE="${REPO_TOKEN}._build.(wsl.)?native"
```

- 调用点：`js` → `CLEAN_PAT_JS`；`native` → `CLEAN_PAT_NATIVE`；**`check`/`wasm` 不再兜底清理**
  （挂死对象是 moon，其 cmdline 不含仓库路径，按 pattern 杀必然误伤别的 lane），改为打印人工处置提示。
- Windows 分支：`Get-CimInstance` 过滤 `Name='node.exe' or Name='moon.exe'` **且** `CommandLine -match $pat`
  （双重收窄），killed 计数为 0 时也打印一行（避免"静默 no-op"重演）。
- WSL 分支：`pgrep -fc` 先计数 → `pkill -f` → 打印实际清理数。
- 新增 `RX_MBT_NO_CLEANUP=1`（保留现场/人工排查用）。

### Q14（P1）PATH 收敛导致清理器静默失效（自测新发现）

`setup_path` 把 PATH 换成 `node:moon:/usr/bin:/bin` 后，`command -v powershell` 必然失败。
修法：在 `detect_platform` 之后、`setup_path` 之前捕获绝对路径：

```bash
PS_EXE=""
for _cand in "$(command -v powershell.exe … || true)" \
             "/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe"; do
  [ -n "$_cand" ] && [ -x "$_cand" ] && { PS_EXE="$_cand"; break; }
done
```
`cleanup_orphans` 改用 `"$PS_EXE"`；为空时打印 `找不到 powershell，无法清理…` 而不是静默 return。

### Q3（P1）跨平台锁：os 归一 + 跨平台不自动回收

**scripts/with_moon_lock.sh**：
- owner 行新增 `os=`（`uname -s` 归一：`MINGW*|MSYS*|CYGWIN*|Windows_NT → windows`、`Linux* → linux`、`Darwin* → macos`）；
  **不能用裸 `uname`**：Windows 的 Git Bash(MINGW) 与 MSYS2(MSYS) 共享同一 pid 命名空间，裸 uname 会把同平台两种
  shell 误判成"跨平台"，反而让陈旧锁永不回收。
- 陈旧判定：**同 host 且同 os** 才允许 `kill -0` 判活并回收；跨平台/跨主机（或旧格式无 `os=` 的锁）一律**不回收**，
  只等待；超时消息打印 `holder` 全文与两种处置方式。
- 新增 `--break-stale`（显式破锁，默认关闭）。

实测（隔离锁目录，避免干扰共享锁）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 同平台陈旧锁（os=windows，pid 已死） | 回收并执行 | ✅ `SAME-PLATFORM-RECLAIMED` |
| 跨平台锁（os=linux，Windows 侧取锁） | 不回收 → 75 | ✅ 等待超时 + holder 全文 |
| `--break-stale` | 破锁并执行 | ✅ `BREAK-STALE-OK` |
| 真实并发（Windows 正在 `moon test test-suit/rhop_business --target js`） | 不偷锁 | ✅ WSL 侧等到 75 超时，未打断对方 |

## 4. 修复过程中的事故与处置（如实记录）

1. **误删共享锁目录**：验证 Q3 的第一次实验里，我在其他 lane 正在 `moon test` 时 `rm -rf .moon-build.lock`，

   共享锁目录现由持有者 trap 正常释放（已确认 `.moon-build.lock` 不存在残留）。

3. **path 收敛 → powershell 不可见**（Q14）：由 E4 首次失败暴露，已修。
4. **轮末 verify 追加一处小加固**：`cleanup_orphans` 增加 `ps_bin` 兜底
