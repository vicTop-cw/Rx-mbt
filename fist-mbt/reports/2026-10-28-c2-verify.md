## 5. ⚠ 新发现 V-1（不阻塞）：测试侧临时目录卫生（`%TEMP%/rhop-*`）

**现象**：跑完一轮 js 套件（819 例）后 `%TEMP%` 新增约 **121 个 `rhop-*` 目录、598KB**。
lead 本轮刚清理 5466 个历史目录（151MB）—— 说明这是**每一轮都会重新长出来**的量级
（5466 ÷ ~121 ≈ 45 轮，与近几轮 gate 运行次数吻合）。

**归因（逐个前缀统计 + 单文件 delta 实验）**：

| 前缀 | 数量 | 归属 |
|---|---|---|
| `rhop-it-*`（cfg/key/session/reverse/relay-share/exec/…） | 51 | `test-suit/rhop_interact/interact_test.mbt` 的 `ffi_tmp()`：`mkdtempSync` 后**不登记退出钩子** |
| `rhop-html-*` | 18 | 其他 js 测试经同类 helper 建的根 |
| `rhop-git-*` | 16 | git 通道相关 js 测试 |
| `rhop-biz-*` | 9 | business 测试根（该包 c2 回归自身 delta=0，说明其收尾是干净的） |
| `rhop-sync-*` | 1 | task_sync 测试 |
| `rhop-relay*` / `rhop-mirror*` / `rhop-task*` | **0 / 0 / 0** | ✅ 产品侧 `relay.stop()`（BUG-1）与 `mirror.mbt` 的 `rhop_temp_workspace` 退出钩子**有效** |

**单文件 delta 实验**（js，隔离测量）：

| 动作 | `%TEMP%/rhop-*` 总数 | delta |
|---|---|---|
| 基线 | 121 | — |
| `moon test test-suit/rhop_interact/interact_test.mbt --target js`（22 例） | 139 | **+18** |
| `moon test test-suit/rhop_business/c2_regression_test.mbt --target js`（6 例） | 139 | **0** |
| `moon test test-suit/rhop_js/relay_test.mbt --target js`（8 例） | 139 | **0** |

**判断**：这不是 C2 那 10 条 P0/P1 的回归（产品侧 relay/mirror 清理确实有效），而是**测试侧**的
资源卫生缺口 —— 多个 js 测试文件各自手写 `ffi_tmp`（`mkdtempSync`）且无退出清理；
产品里其实已有带退出钩子的 `rhop_temp_workspace`，但测试没用它。

**建议修法（下轮/owner）**：
1. 测试统一改用 `@rp.rhop_temp_workspace("rhop-xx-")`（已带 exit 钩子），或
2. 每个 js 测试文件末尾加"收尾守卫"用例（同级已有先例：`relay_test` 的注册表清零守卫、
   `task_store_test` 的句柄清零守卫），统一 `rm -rf` 本轮根目录；或
3. gate 收尾兜底：在 `test_all.sh` 里对 `$TMPDIR/%TEMP%` 下本轮前缀做清理（可行但要小心误删，
   本次未做，避免把"测试责任"藏进 gate）。

**本轮处置**：已把本次 verify 产生的残留清空（`before=139 → after=0`），避免继续累积。
